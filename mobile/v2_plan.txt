## Context

KaamNow is migrating from a hard role-split (customer OR worker) to an OLX-style unified model where any user can both hire and work. Workers are now called "Local Experts" throughout. Simultaneously adding: GPS, free AI (Gemini Flash + Groq Whisper), in-app chat (Chatwoot self-hosted), worker certifications + video profile, gender, payments (Razorpay test mode), wallet credits (refer & earn ₹100/₹50, 90-day expiry), dispute/report system, portfolio photos, urgent/asap jobs, saved Local Experts, KYC (DigiLocker), offline mode, job templates, recurring bookings, photo-to-job AI, voice-to-job AI, earnings calendar + goal, available-from scheduling, "Available Now" broadcast, OTP for job start (Swiggy-style), GPS check-in, before/after job photos, job progress updates, completion certificate PDF, quick re-hire, post job anonymously, waiting list for Local Experts, QR code profile, in-app referral wallet screen, T&C + Privacy Policy in-app, unified FAQ, report an issue, emergency contact, saved addresses, seasonal job templates, nudge notifications, skill badges auto-award, profile verification selfie, first-time walkthrough, PostHog analytics, Sentry monitoring, English + Hindi + Bhojpuri + Maithili i18n (centralized), and a fully simplified mobile app (18 screens → 13, single unified nav).

The WhatsApp onboarding bot is NOT touched. Only push + in-app notifications are used for engagement events.

## Core UX & Language Principles (NON-NEGOTIABLE)

These apply to every screen, every string, every interaction across mobile and web.

### 1. Plain English — Simple Language Only

Every label, button, message, and error must use the simplest possible English. No jargon, no technical terms, no complex sentences. Write as if explaining to someone who learned English as a second language.

**Examples:**
| ❌ Don't use | ✅ Use instead |
|---|---|
| "Initiate Engagement" | "Send Request" |
| "Terminate Contract" | "Cancel Job" |
| "Verified Professional" | "Trusted Worker" |
| "Authentication Required" | "Please log in first" |
| "Availability Status" | "Are you free?" |
| "Submit Application" | "Apply for Job" |
| "Profile Completion" | "Your Profile" |
| "Insufficient Permissions" | "You can't do this" |

### 2. Respectful Naming — Always Dignified

This app serves blue-collar workers. Every label, heading, and piece of copy must treat them with full dignity. Never use words that feel condescending or transactional.

**Rules:**
- Workers are called **"Workers"** or by their name — never "labourers", "help", "servants", "maids" (use "Home Helper", "Cleaner")
- Customers are called **"Customers"** or by their name — never "employers", "owners", "masters"
- Job categories use respectful names: "Home Cleaning" not "Maid Work", "Cooking Help" not "Cook Servant"
- Ratings ask "How was your experience?" not "Rate this worker"
- Earnings shown as "You earned ₹500" not "Payment sent to worker"
- Profile shown as "Your Skills" not "Worker Skills"
- Trust tier names: "New" (1), "Trusted" (2), "Pro" (3), "Star" (4) — not "Basic/Verified/Pro/Elite"

### 3. English-Hindi Toggle — Centralized i18n System

**Single source of truth:** One file `mobile/src/i18n/translations.js` contains ALL strings for both languages. No hardcoded strings anywhere in mobile or frontend.

**Architecture:**

```
mobile/src/i18n/
  translations.js       ← ALL strings, both languages, keyed
  index.js              ← exports useTranslation() hook

frontend/src/i18n/
  translations.js       ← same structure, web-specific strings added

```

- On change: syncs to `PATCH /api/auth/me` (`preferred_language` field) if user is logged in
- Server-generated content (notification text) uses `user.preferred_language` from DB — already stored

**Backend notifications — Hindi support:**

- Selection: `lang = user.get("preferred_language", "en")`

### 4. UX Simplicity Rules

Every screen must follow these rules without exception:

**Maximum 3 actions per screen.** If a screen has more than 3 buttons/actions, split it or hide secondary actions behind a "More" button.

**One primary action per screen.** The most important action gets the big button. Everything else is secondary.

**No modals on top of modals.** Max 1 level of overlay.

**No forms longer than 4 fields visible at once.** Use steps/wizard if more fields needed.

**Every action has feedback within 300ms.** Loading spinner, disabled state, or visual change immediately on tap.

**Error messages are always actionable.** Never just "Error". Always "No internet — tap to retry" or "Name is required — please add your name".

**Empty states always have a CTA.** Never just "No results". Always "No jobs near you yet — try a different pincode" with a button.

**Numbers are always formatted for India:** ₹ prefix, Indian number system (1,00,000 not 100,000), dates in DD MMM format ("15 Jun").

### 5. Backend-Heavy Architecture

**The mobile app and web frontend are thin clients.** All business logic lives in the backend. Frontend/mobile responsibilities are limited to:
- Displaying data returned by the API
- Capturing user input
- Showing loading/error/empty states
- Navigation

**Forbidden in frontend/mobile:**
- Business rule calculations (ratings, tier logic, matching algorithms)
- Data validation beyond basic "field is required"
- Price calculations
- Permission checks (always re-verified by backend)
- Engagement state machine logic

**Every user action triggers an API call.** Nothing is computed locally and then assumed correct. The backend is the single source of truth.

## Credential Store — Doppler Setup

**All secrets managed through Doppler (free forever, up to 3 projects).** No `.env` files in repo. No hardcoded values anywhere.

```bash
# Local dev
doppler run -- uvicorn backend.app:app --reload

# k8s
# Doppler operator syncs → k8s Secret → pod env vars automatically

# EAS mobile build
# Doppler secrets → EAS environment variables via CLI
```

**Rule:** Gemini, Groq, Razorpay, Cloudinary, MongoDB credentials — **backend Doppler only**.
Mobile app only receives: `EXPO_PUBLIC_API_URL`, `EXPO_PUBLIC_SENTRY_DSN`, `EXPO_PUBLIC_POSTHOG_KEY` — safe to expose in bundle.

**Setup steps (Day 1 before any code):**
1. Create Doppler account → new project `kaamnow`
2. Create environments: `dev`, `staging`, `production`
3. Add all env vars from `.env.dev` into Doppler `dev`
4. Add all new env vars (Gemini, Groq, Razorpay, PostHog, Sentry, Chatwoot)
5. Install Doppler CLI + k8s operator
6. Delete all `.env` files from repo — add to `.gitignore`
7. Update `README.md` with Doppler setup instructions
